# ESG Internship Bot

Телеграм-бот в формате интерактивной стажировки по ESG-терминам. Пользователь проходит 5 учебных дней в виде имитации корпоративной переписки с руководителем и наставником, отвечает на вопросы, а в конце сдает финальный тест, попадает в рейтинг и получает сертификат с уникальным номером.

---

## О проекте

Этот проект создан как учебный продукт для студентов 1 курса программы **«Стратегия и продюсирование в коммуникациях»** факультета креативных индустрий НИУ ВШЭ.

### Цель проекта

Создать понятный и вовлекающий способ изучения ESG-терминов для зумеров через знакомый формат — **чат в Telegram**.

Вместо «сухого» учебника пользователь проходит стажировку внутри вымышленной компании:
- **Владимир Алексеевич** — руководитель, который ставит задачи;
- **Лиза** — наставник, которая объясняет термины простым языком;
- пользователь — **стажёр**, который проходит обучение день за днём.

Такой подход помогает:
- упростить восприятие сложных ESG-терминов;
- повысить вовлечённость;
- сделать обучение интерактивным и игровым;
- адаптировать серьёзную ESG-повестку под молодую аудиторию.

---

## Что умеет бот

### Основной функционал

- регистрация пользователя;
- прохождение **5 дней стажировки**;
- сценарное обучение в формате корпоративной переписки;
- поддержка разных типов шагов:
  - обычные сообщения,
  - сообщения с паузой,
  - одиночные вопросы,
  - множественный выбор,
  - завершение дня;
- автоматический переход между шагами;
- финальный тест из **27 вопросов**;
- подсчёт результата в 100-балльной системе;
- рейтинг стажёров;
- выдача **уникального номера сертификата** после завершения;
- проверка сертификата через команду:
  - `/check-certificate 12345`
- просмотр рейтинга через команду:
  - `/rating`

### Дополнительный функционал

- рандомное перемешивание кнопок в тестах и вопросах;
- заглушки для видео и голосовых сообщений в текстовом формате;
- сидирование БД мок-данными через `mock.py`;
- полная очистка проекта для разработки через `recleaner.py`;
- хранение токена в `token.txt`, а не в коде;
- безопасная подготовка проекта к публичному репозиторию.

## Локальный запуск

### 1. Клонировать проект

```bash
git clone https://github.com/3qual/esg_internship_bot.git
cd esg_internship_bot
```

### 2. Создать виртуальное окружение

#### macOS / Linux

```bash
python3 -m venv venv
source venv/bin/activate
```

#### Windows (PowerShell)

```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

#### Windows (cmd)

```cmd
python -m venv venv
venv\Scripts\activate.bat
```

### 3. Установить зависимости

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Создать `token.txt`

В корне проекта нужно создать файл `token.txt` и вставить туда токен Telegram-бота:

```text
1234567890:AAExampleRealTelegramBotTokenHere
```

Важно:
- в файле должна быть **только одна строка** с токеном;
- без кавычек;
- без пробелов до и после;
- файл **не должен попадать в Git**.

### 5. Запустить бота

```bash
python3 bot.py
```

Если всё настроено правильно, в консоли появится лог запуска, а бот начнёт работать в режиме polling.

## Как получить токен бота

1. Открой [@BotFather](https://t.me/BotFather)
2. Введи команду `/newbot`
3. Следуй инструкциям
4. Скопируй выданный токен
5. Вставь его в `token.txt`

Если токен уже попадал в Git или кто-то мог его увидеть:
- открой BotFather,
- выбери бота,
- перевыпусти токен.

## Безопасность

Проект подготовлен к публикации в публичный репозиторий.

### Sensitive-данные не должны храниться в Git

В `.gitignore` обязательно должны быть:

```gitignore
token.txt
esg_bot.db
backups/
__pycache__/
*.pyc
*.pyo
*.log
logs/
```

### Важно

Если файл уже был добавлен в Git раньше, одного `.gitignore` недостаточно. Нужно убрать его из индекса:

```bash
git rm --cached token.txt
git rm --cached esg_bot.db
git rm -r --cached backups/
git rm -r --cached __pycache__/
git commit -m "Remove local and sensitive files from git tracking"
git push
```

## Сертификаты

После завершения обучения и финального теста пользователь получает:
- результат,
- место в рейтинге,
- **номер сертификата**.

Номер сертификата:
- уникальный;
- пятизначный;
- сохраняется в БД;
- может быть проверен любым пользователем через команду:

```bash
/check-certificate 12345
```

Бот покажет:
- имя владельца сертификата;
- его баллы;
- дату выдачи сертификата.

## Финальный тест и рейтинг

После прохождения всех 5 дней пользователь может начать финальный тест.

### Особенности теста

- 27 вопросов;
- таймер начинается автоматически;
- ответы перемешиваются случайным образом;
- считается итоговый результат в шкале 0–100;
- результат записывается в рейтинг;
- рейтинг сортируется по:
  1. баллам,
  2. времени прохождения.

### Просмотр рейтинга

Через команду:

```bash
/rating
```

Особенность:
- строка текущего пользователя в рейтинге выделяется **жирным и подчёркнутым**.

## Логика сценария

Бот построен как последовательность шагов, которые хранятся в `content/dayX.py`.

### Поддерживаемые типы шагов

- `message`
- `message_pause`
- `question_single`
- `question_multi`
- `question_single_forced`
- `system_message`
- `day_end`

### Как это работает

- контент каждого дня описывается в виде массива `STEPS`;
- движок в `handlers/days.py` читает шаги по порядку;
- прогресс пользователя хранится в БД;
- после завершения дня открывается следующий;
- после пятого дня открывается финальный тест.

## Особенности реализации

### 1. Рандомизация кнопок
Во всех вопросах порядок ответов перемешивается, чтобы правильный вариант не был всегда первым.

### 2. Заглушки для медиа
Если по сценарию должно быть видео или голосовое, бот пока отправляет текстовые заглушки вида:

```text
[Видео — описание]
[Голосовое — описание]
```

Это позволяет не ломать сценарий до загрузки реальных медиафайлов.

### 3. Миграции БД
`database.py` поддерживает добавление новых колонок в уже существующую базу при запуске.

### 4. Разделение логики
- сценарий хранится отдельно от движка;
- клавиатуры вынесены отдельно;
- логика рейтинга изолирована;
- финальный тест обрабатывается отдельно от учебных дней.

## Автозапуск через systemd

### Создай unit-файл

```bash
sudo nano /etc/systemd/system/esg-bot.service
```

Вставь:

```ini
[Unit]
Description=ESG Internship Telegram Bot
After=network.target

[Service]
User=YOUR_USER
WorkingDirectory=/home/YOUR_USER/esg_internship_bot
ExecStart=/home/YOUR_USER/esg_internship_bot/venv/bin/python /home/YOUR_USER/esg_internship_bot/bot.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Замени:
- `YOUR_USER` на имя пользователя на сервере.

### Перезапусти systemd и включи сервис

```bash
sudo systemctl daemon-reload
sudo systemctl enable esg-bot
sudo systemctl start esg-bot
```

### Проверить статус

```bash
sudo systemctl status esg-bot
```

### Смотреть логи

```bash
journalctl -u esg-bot -f
```

## Частые проблемы

### `.gitignore` не срабатывает
Если файл уже был закоммичен, нужно убрать его из индекса через:

```bash
git rm --cached token.txt
```

### Бот не запускается
Проверь:
- существует ли `token.txt`;
- установлен ли `venv`;
- установлены ли зависимости;
- нет ли ошибки в `requirements.txt`.

### БД «сломалась» после тестов
Используй:

```bash
python3 recleaner.py -y
```

или восстанови бэкап.

### После изменения БД не появились новые поля
Просто перезапусти бота — `init_db()` должен выполнить миграции автоматически.
